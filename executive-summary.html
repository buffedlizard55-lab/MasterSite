How to read this summary

The first three columns answer “what, where, how fresh” — the rest answer “should I worry?”

First 3 columns

  • Website — display name, repository id, and a one-line description.
  • Live link — direct link to the published site (tap Visit ↗). The small Repo link goes to the source.
  • Last updated — newest commit on the default branch, with a plain-English age (“2 days ago”). Newest first by default.

Stats & flags after that

  • Category / Type / Build — what it is, real app vs. doc stub, and recorded Pages status.
  • Commits — total default-branch commits: a quick proxy for how actively built it is.
  • Created — repository age.
  • Health — ✓ Healthy means no flags and a real app; ⚠ Review means an auditor flagged something (hover/tap for the reason); 📝 Stub means a placeholder awaiting real content.

Data source: the same verified snapshot as the full directory (data/sites.js, generated —). Timestamps are UTC. Build status is the recorded snapshot value, not a live uptime check. For full telemetry, per-entry audit flags and the irregularity register, see the full directory.
