How to read this summary

The first three columns answer “what, where, how fresh” — the rest answer “should I worry?”

First 3 columns

  • Website — display name, repository id, and a one-line description.
  • Live link — direct link to the published site (tap Visit ↗). The small Repo link goes to the source.
  • Last commit — newest committer timestamp on the default branch, with a plain-English age. This is not a last-use or visit timestamp; newest first by default.

Stats & flags after that

  • Category / Type / Build — what it is, whether an index.html exists at the configured Pages path, and the recorded Pages status.
  • Commits — total default-branch commits: a quick proxy for how actively built it is.
  • Created — repository age.
  • Review state — ✓ No flags means no per-entry audit flag is recorded (not an uptime check); ⚠ Review means an audit flag is present; 📝 Stub means no HTML entry point exists at the configured Pages path.

Data source: the same verified snapshot as the full directory (data/sites.js, generated —). Timestamps are UTC. Build status is the recorded snapshot value, not a live uptime check; GitHub does not expose site visits/last use. For source bases, full telemetry, per-entry audit flags and the irregularity register, see the full directory.
