How to read this summary

The first three columns answer “what, where, how fresh” — the rest answer “should I review it?”

First 3 columns

  • Website — display name, repository id, and a sourced description from the repository’s own files.
  • Live & Review Links — direct link to the published site (Visit ↗), the source repository (Repo), and the official GitHub REST API endpoints (Repo API, Pages API, Commits API, plus the per-site JSON record in data/sites/) for manual line-by-line review.
  • Last commit — newest committer timestamp on the default branch, with a plain-English age relative to the snapshot and the description verification stamp (prose: <sha>). GitHub’s public API exposes no site visits or last-use timestamp.

Stats & flags after that

  • Category / Type / Build — curated category, whether an index.html exists at the configured Pages path, and the recorded Pages build status.
  • Commits / Created — default-branch commit count and repository created_at date (with initial commit SHA).
  • Review state — ✓ No flags means the description stamp matches the recorded head, Pages status is built, and no per-entry audit flag is recorded (not an uptime check); ⚠ Review means an audit flag is present, the description SHA is behind the recorded head (PROSE-STALE), the stamp is missing, or Pages status is not built; 📝 Stub means no HTML entry point exists at the configured Pages path.

Data source: the same verified snapshot as the full directory (data/sites.js, generated —). Timestamps are UTC. Build status is the recorded snapshot value, not a live uptime check; GitHub does not expose site visits/last use.
